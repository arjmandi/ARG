# Cold-Start Evaluation — the owner's walkthrough vs. the design (feasibility verdict)

*Response to the owner's directive (2026-07-17): evaluate the zero-knowledge ARC experience ("arrive knowing nothing; one goal: win; actions as tools; environment as input; a processing cycle; the LLM fills the sub-goals from the first screen; the load-bearing feasibility check at maximal ambiguity") against docs_arg_design.md + the goal-chaining proposal; judge the ARG-as-library idea; ground the small-model hypothesis. Verdict first, then the cycle-by-cycle trace, then the deltas.*

---

## Verdict

**Feasible — and the walkthrough is almost exactly what the chaining proposal's recognizer produces, including the zero-context state.** The design already holds the owner's frame in its bones (§7: "nothing above the adapter knows what a game is"; §4.3 step 5: "under ignorance the answer is always a probe"; §3: expandable axioms; A6: curriculum-optional). Four deltas are required to make the walkthrough literally true of the system, none of which bends an invariant:

1. **Generative curriculum as the tested default** (the owner's "maybe it's better to at least try this sub-goal mechanism"): run with `ARG_SEEDS=0` + the chaining engine, so the LEARN-chain is *generated by the Surveyor from the first deficit* rather than pre-seeded. The seeds become the ablation (A6 inverted). The flag exists; the deficit loop is the missing engine (proposal G1–G3).
2. **Grammar completion for from-scratch curriculum goals:** "learn the actions/rules" as *generated* tests needs `COUNT(entity, where={status/…}) ≥ k` — a small completion of amendment A1 (counts with status filters over stamped rows), already implied but not spelled out.
3. **Tools at the seam** (the part of de-ARC worth doing now): the adapter already returns `{action, param_schema}` — formalize it as `Tool{name, param_schema, side: actuate|observe, description}` and make the loop/means-analysis/frontier consume tool descriptors instead of `== "ACTION6"` string checks. This kills the ARC-isms exactly where the owner fears bias (my earlier LEARN-ACTIONS-over-available fix was a patch a tool schema would have made unnecessary: tools declare their own availability).
4. **Cold-start tests as first-class:** the zero-state (no referents, no rules, no observation) must be a pinned unit test of the recognizer: `chain_status(G0) = DEFICIT(total)` whose only executable behavior is tool exploration — the "feasibility check when ambiguity is very high," verified, not assumed.

**On ARG-as-library:** right instinct, staged wrong if done now — full extraction with a single instantiation is how libraries over-abstract. Recommendation below (§3): take the *tool seam* now, extract the *library* when the P3 TextSpan instantiation lands, so the abstraction is cut against two real consumers. The design's own §7 table already plans for exactly that moment.

## 2. The feasibility check at maximal ambiguity (the state the owner insists on)

The proposal's recognizer handles the zero-context state without special-casing, and this must be pinned as its first test:

- `needs(G0)` = its effect keys; no rules → no EXECUTABLE; no children → no coverage → `DEFICIT(H)` where every hole carries **empty derivable evidence** (no HYPOTHESIS rules, no receipted referents, empty action model).
- Empty-evidence holes are the definition of "explore": the walk's fallback probes tools (§4.3 step 5), and the deficit brief to the Surveyor says, in machine terms, "goal + tools + (maybe) a screen; no connections exist" — which is precisely the prompt from which any competent LM generates the curriculum chain.
- Every later cycle strictly reduces ambiguity through receipts; `chain_status` is recomputed each beat, so "enough now?" is asked continuously, mechanically, for free.

So the design does not need a separate "high-ambiguity mode": total deficit *is* the high-ambiguity state, and its behavior (probe + directed expansion) falls out of the same computation that later says "align and execute."

## 3. ARG-as-library — my judgment, as requested

**The bias worry is legitimate and already partially realized.** Concrete ARC-isms that leaked above the adapter: `== "ACTION6"` branches in frontier/means/realization; the {x,y} param shape in three places; LEARN-ACTIONS originally quantifying the fixed 7-action vocabulary; RESET as beat 0. Each cost us a live fix or a narrowing. A tool-schema'd seam would have prevented three of the four.

**But full extraction now is the wrong stage.** A library cut against one consumer bakes that consumer's shape into its interfaces — the same bias, one layer down and harder to see. The design already schedules the correct forcing function: the **P3 TextSpan instantiation** (deterministic re-read engine over documents) is the second consumer, and §7's table is the extraction blueprint (Locator/Consequence/Rule/Goal/View per instantiation).

**Recommendation (staged):**
1. **Now, inside G1–G3:** the tool seam (delta 3). Adapter exposes `tools()`; the loop, means analysis, frontier, and R8 consume descriptors (`side`, `param_schema`, `targeted: bool`) — no string-matched action names above the adapter. Contained diff, immediately testable, kills the known bias class.
2. **With P3:** extract `arg/` into the transport-agnostic library — the cycle as `arg.step(observation) → command`, environments as {tools, observe-fn} pairs, ARC and TextSpan as the two shipped adapters. That is also the natural Kaggle/MIT packaging moment the design already commits to.

## 4. The small-model hypothesis, grounded in instruments we already have

The owner's hypothesis — a small model suffices because the hard parts are structural — is *exactly* what the deficit mechanism makes testable, because it converts the LLM's job from open-ended invention to **slot-filling against a machine-stated question in a closed grammar**. That is the regime where small/fine-tuned models close gaps. Measurement plan (no new instruments needed):

- **Decomposition quality per backbone** = gate-rejection profile of PROPOSE_GOAL (incompilable / duplicate / unverifiable-fill rates) + time-to-first-VALIDATED sub-goal (A6's readout) + holes-filled-per-epoch + milestone conversion (milestone ACCEPTED → parent compilable). All computed from existing tables, reported per `ARG_MODEL` exactly as WER already is (the P4 discipline).
- **The pre-registered expectation:** deficit-directed proposals show a much flatter quality curve across model sizes than open-ended proposals — testable by running the same G3 batch with `ARG_MODEL` ∈ {sonnet-5, haiku-class, small open-weight} once the engine lands.
- If a small model's goal quality is the binding constraint, it prints as a named number (not a vibe), and the fine-tuning route has a training signal: the gate-rejection classes are labels.

## 5. Amended plan (supersedes the proposal's G-plan; A1/A2 read as blessed)

- **G1** — recognizer + edges + grammar (incl. delta-2 COUNT/status forms) + **cold-start pinned tests** (zero-state DEFICIT; empty-evidence holes → probe; first-screen deficit brief content).
- **G2** — walk-frontier execution + auto-fill tier + DEFICIT stamps + **tool seam** (delta 3: adapter `tools()`, de-string the loop).
- **G3** — Surveyor DEFICIT block + `fills_hole` ingest + **generative-curriculum default** (`ARG_SEEDS=0` becomes the FULL cell's configuration; seeded LEARN-* becomes the A6 ablation arm) — then batch 4 on ls20: FULL ×3 ×400 actions under generation, against the proposal's falsified-if, plus one small-backbone lane for the first decomposition-quality-per-tier readout.
- Library extraction: deferred to the P3 instantiation, per §3.

**Falsified-if additions (pre-registered):** the generated curriculum fails to include action/rule-learning-shaped goals on ≥2 of 3 seeds (then generic-decomposition is NOT model-easy and the seeds were load-bearing — reported as A6's honest outcome); or the cold-start recognizer ever reports anything but total DEFICIT on an empty store.
