# ARG Implementation-Verification Report

## Verdict

**The implementation faithfully serves the design.** Nine of the ten load-bearing invariants are SERVED by concrete, verified mechanisms — not by convention or hope, but by structural constructs that make the failure case impossible (closed-set DB CHECKs, append-only triggers with `RAISE(ABORT)`, a validate-gate choke point that no LLM output bypasses, and a byte-identical-by-construction join). No gap touches trust, grounding, or state integrity; the single gap is a bounded resource-ceiling edge that requires atypical stored goal JSON to trigger. Ship-quality with one follow-up.

## Gaps, ranked by severity

### 1. render-ceiling-O-working-set — MINOR

**What's wrong.** `renderer.py:budgeted_view` sheds zones under budget pressure (drops Z3/Z4 corroboration, then collapses to the irreducible Z1+Z6) but **never clamps or truncates the final text against `B_RENDER`**. `z6_goal_card` (lines 213-214) emits the goal's raw `statement` and `achievement_test_json` with no length bound — an O(store-content) term living inside a zone that both fallbacks preserve. After the final collapse to Z1+Z6 there is no re-check and no truncation, so `budgeted_view` can return an over-`B` view and the caller feeds an over-ceiling render to the LLM. This also means render size is not strictly O(working set).

**Secondary.** Token accounting is hardcoded to `est_tokens` (char/4, line 30). The docstring's "may swap Anthropic `count_tokens`" has no mechanism in this file, so a char/4 underestimate can breach the real token ceiling while `est <= B`.

**Failure case.** A goal with a large `achievement_test_json`/`statement` makes Z6 alone exceed `B_RENDER`; both fallbacks preserve Z6 → over-ceiling render reaches the LLM.

**Why minor, not worse.** All working-set-derived zones (Z2/Z4/Z5/Z6 bindings) are cap-bounded, `working_set` caps at `config.W_WORKING_SET` (`return kept[:W]`, line 118), and `render_tokens` is stamped and observable (line 265, per-zone at 277). A breach requires atypical stored goal JSON rather than normal operation, and it is detectable after the fact via the stamped token count. No trust/grounding/integrity impact.

**Concrete fix.** In `budgeted_view`, after the Z1+Z6 collapse, add a terminal hard clamp: if `est_tokens(view) > B_RENDER`, truncate the Z6 `statement`/`achievement_test_json` fields to a bounded prefix (with an explicit `…[truncated]` marker so legibility stays honest) and re-measure, guaranteeing the returned view is `<= B`. Separately, either wire the promised Anthropic `count_tokens` path or delete the docstring claim so the char/4 estimate isn't presented as a real ceiling; if kept, size the clamp with a safety margin below `B_RENDER` to absorb char/4 underestimation.

## Post-verification: the one MINOR gap is fixed

The `render-ceiling-O-working-set` gap was closed in `renderer.py:budgeted_view` with a terminal hard clamp: after the Z1+Z6 collapse, if the view still exceeds a safety-margined character cap (B·4·0.9, absorbing the char/4 estimator's underestimation), it is truncated to a bounded prefix with an honest `…[render clamped to B]` marker and re-measured — so the returned view is ALWAYS ≤ B, a guarantee rather than best-effort. Verified: an 80,000-char active goal renders at 5,412 tokens (test_arg_renderer). **All 10 invariants now served.**
